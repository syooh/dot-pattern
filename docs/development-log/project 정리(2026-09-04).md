# 1. 프로젝트 개요

## 프로젝트명

Dot Pattern Editor

## 프로젝트 목적

이미지를 기반으로 도트 패턴을 생성하고, 생성된 패턴을 웹에서 직접 편집할 수 있는 Editor를 개발한다.

단순히 이미지를 픽셀 형태로 변환하는 것에서 끝나지 않고, 생성된 패턴을 직접 수정하고 저장하며, 향후 뜨개질 및 패턴 작업에 활용할 수 있는 웹 기반 Pattern Editor로 확장하는 것을 목표로 한다.

## 주요 목표

- 이미지 → 도트 패턴 변환
- 패턴 크기 지정
- 색상 수 지정
- Pattern Editor를 통한 직접 편집
- Brush / Eraser / Fill / Select / Move
- Undo / Redo
- Rotate / Flip
- Zoom / Grid
- Palette 관리
- 색상 추가 / 삭제
- JSON 저장 / 불러오기
- PNG 저장
- Edit Mode / View Mode
- 현재 작업 행 표시
- 작업 진행률 표시
- Row / Column Header
- 향후 사용자 계정
- 향후 Pattern 저장 및 관리
- 향후 Django REST Framework + MySQL + JWT 연동

# 5. PatternData 설계

패턴 데이터를 관리하기 위해 `PatternData`를 정의하였다.

    export interface PaletteColor {
        id: number;
        hex: string;
        name: string;
        code?: string;
        brand?: string;
        symbol?: string;
        count?: number;
    }

    export interface PatternData {
        width: number;
        height: number;
        palette: PaletteColor[];
        pixels: number[][];
    }

    export type ToolType =
        | "brush"
        | "eraser"
        | "fill"
        | "select"
        | "move";

PatternData는 다음 구조로 관리된다.

    PatternData
    ├── width
    ├── height
    ├── palette
    └── pixels

각 Pixel에는 실제 색상값을 직접 저장하는 것이 아니라 Palette Color의 ID를 저장한다.

예를 들어:

    pixels[y][x] = colorId

와 같은 방식으로 Pixel과 Palette를 연결한다.

이 구조를 사용하면 Palette 정보를 변경하거나 관리하기 쉬우며, JSON으로 저장하기에도 적합하다.

# 6. Palette 데이터 설계

Palette Color는 다음 정보를 저장할 수 있도록 설계하였다.

- id
- hex
- name
- code
- brand
- symbol
- count

향후 실제 뜨개실 색상 데이터와 연결할 수 있도록 확장성을 고려하였다.

예상 구조:

    {
        id: 1,
        hex: "#FFFFFF",
        name: "White",
        code: "B5200",
        brand: "DMC",
        symbol: "A",
        count: 120
    }

현재는 기본적인 색상 정보 중심으로 사용하고 있으며, 실제 DMC 등의 색상 데이터 연동은 향후 기능으로 남겨두었다.

# 7. Pattern 생성 기능

이미지를 업로드하면 Backend에서 이미지를 분석하여 도트 패턴으로 변환한다.

전체 처리 과정은 다음과 같다.

    이미지 업로드
        ↓
    이미지 크기 조정
        ↓
    색상 수 설정
        ↓
    K-Means 색상 양자화
        ↓
    Palette 생성
        ↓
    Pixel 데이터 생성
        ↓
    PatternData 반환
        ↓
    React Editor 표시

이미지 처리는 Pillow를 사용하고, 색상 양자화는 scikit-learn의 K-Means를 사용한다.

# 8. 이미지 크기 처리

사용자가 원하는 Pattern 크기에 맞게 원본 이미지를 Resize한다.

기본적으로 Pattern의 width와 height를 기준으로 이미지를 변환한다.

기존 개발 과정에서는 Pillow의 Resize 기능을 사용하였다.

    img.resize(
        (WIDTH, HEIGHT),
        Image.Resampling.NEAREST
    )

도트 패턴의 특성상 픽셀 단위의 결과를 유지하기 위해 NEAREST 방식을 사용하였다.

# 9. FastAPI Backend

현재 Backend는 FastAPI를 사용한다.

주요 API는 다음과 같다.

    POST /generate

Frontend에서 이미지와 패턴 생성 정보를 FormData로 전달하면 Backend에서 PatternData를 생성하여 반환한다.

전달 정보:

- image
- width
- height
- colors

전체 구조:

    React
      ↓
    POST /generate
      ↓
    FastAPI
      ↓
    Image Processing
      ↓
    Color Quantization
      ↓
    Pattern Generation
      ↓
    PatternData
      ↓
    React

현재 Backend의 Web API 역할은 FastAPI의 `app.py`에서 담당한다.

`main.py`는 별도의 테스트 / CLI 성격의 코드로 구분하였다.

# 12. PatternEngine

PatternData를 직접 수정하는 로직은 PatternEngine으로 분리하였다.

PatternEngine은 Canvas를 직접 조작하지 않는다.

주요 역할:

- Pixel 수정
- Pattern 복사
- Selection 데이터 복사
- Clipboard 처리
- Paste
- Selection 이동
- Selection 반전
- Selection Fill

주요 함수:

    clonePattern()
    paintPixel()
    copySelectionData()
    pasteClipboard()
    flipHorizontal()
    fillSelection()

이렇게 Engine과 Canvas를 분리함으로써 데이터 처리 로직과 화면 렌더링 로직을 독립적으로 관리할 수 있도록 하였다.

# 15. Brush

Brush는 선택된 색상을 Pixel에 적용하는 기본 편집 도구이다.

Canvas에서 Cell을 클릭하거나 드래그하면 해당 위치의 Pixel 색상이 변경된다.

기본 흐름:

    Canvas Mouse Event
        ↓
    Cell 좌표 계산
        ↓
    paintPixel()
        ↓
    PatternData 변경
        ↓
    Canvas 재렌더링

---

# 16. Eraser

Eraser는 선택된 Cell의 색상을 지우는 기능이다.

Brush와 동일한 Canvas 이벤트 구조를 사용하지만 Pixel에 적용하는 색상 처리 방식이 다르다.

---

# 17. Fill

Fill 기능을 추가하였다.

사용자가 특정 영역을 클릭하면 연결된 동일 영역을 선택된 색상으로 채운다.

Fill 기능을 통해 큰 영역을 하나씩 Brush로 칠하지 않고 한 번에 변경할 수 있도록 하였다.

---

# 18. Select

Selection은 별도의 상태로 관리한다.

    Selection
        ↓
    Selection 영역 계산
        ↓

# 19. Move

# 24. Canvas 구조

Canvas 기능이 복잡해짐에 따라 하나의 파일에서 모든 렌더링을 처리하지 않고 Layer 구조로 분리하였다.

기본 구조:

    PatternCanvas
        ↓
    CanvasRenderer
        ↓
    Canvas Layers

PatternCanvas는 Canvas Element와 이벤트를 관리한다.

CanvasRenderer는 실제 렌더링 순서를 관리한다.

# 26. PixelLayer

PixelLayer에서는 PatternData의 pixels를 순회하여 Palette의 색상을 Canvas에 그린다.

기본적인 방식:

    pattern.pixels[y][x]
        ↓
    colorId
        ↓
    pattern.palette
        ↓
    color.hex
        ↓
    Canvas fillRect()

이를 통해 PatternData와 Canvas 표시를 연결하였다.

---

# 27. GridLayer

Pattern의 Cell 구분을 위해 Grid를 표시한다.

일반 Grid와 Bold Grid를 구분하였다.

현재 기준:

- 일반 Grid: 1칸 단위
- Bold Grid: 10칸 단위

10칸마다 Bold Grid를 표시하여 큰 패턴에서도 현재 위치를 쉽게 파악할 수 있도록 하였다.

# 30. Camera / Zoom

    └── offset

Zoom 기능은 Edit Mode와 View Mode 모두에서 사용할 수 있도록 하였다.

# 33. Row / Column Header

Pattern의 위치를 쉽게 확인하기 위해 Canvas 상단과 왼쪽에 Header를 추가하였다.

번호는 1부터 시작하도록 변경하였다.

실제 뜨개 작업 방향을 고려하여 번호 방향도 조정하였다.

기준:

    오른쪽 아래 = (1, 1)

즉 Pattern의 좌표가 실제 작업 방향과 자연스럽게 연결되도록 구성하였다.

Hover 중인 Cell과 해당 Header도 강조하여 현재 위치를 쉽게 파악할 수 있도록 하였다.

# 48. View Mode 편집 차단

실제 Canvas Event에서도 편집 기능을 차단하였다.

# 49. Canvas Mouse Event의 Mode 처리

Canvas MouseDown 이벤트에서 Mode를 먼저 확인하도록 변경하였다.

기본적인 처리 방식:

    if (mode === "view") {
        const row = patternHeight - y;
        onCurrentRowChange(row);
        return;
    }

View Mode에서는 Pattern 편집 로직으로 넘어가지 않고 Current Row 변경만 처리한다.

이를 통해 View Mode에서 Canvas를 클릭해도 Pattern이 변경되지 않도록 하였다.

# 51. Current Row

View Mode의 핵심 기능으로 현재 작업 중인 행을 표시하였다.

상태:

    const [currentRow, setCurrentRow] = useState(1);

View Mode에 진입하면 Current Row를 1로 초기화한다.

즉 View Mode를 처음 열었을 때 첫 번째 Row가 현재 작업 행이 된다.

---

# 52. Current Row Layer

Current Row를 Canvas에서 시각적으로 표시하기 위해 `CurrentRowLayer`를 추가하였다.

초기에는 현재 Row 전체를 반투명한 노란색으로 채우는 방식으로 구현하였다.

하지만 Pattern의 실제 색상을 가리는 문제가 있었기 때문에 최종적으로 Border 방식으로 변경하였다.

현재 방식:

    현재 작업 Row
    ┌─────────────────────────────┐
    │                             │
    └─────────────────────────────┘

빨간색 Border를 사용하여 Pattern의 실제 색상을 최대한 가리지 않도록 하였다.

---

# 53. Current Row는 View Mode에서만 표시

Current Row Highlight는 Edit Mode에서는 표시하지 않는다.

CanvasRenderState에 Mode를 추가하였다.

    mode: "edit" | "view";

CanvasRenderer에서:

    if (state.mode === "view") {
        drawCurrentRow(ctx, state);
    }

형태로 처리한다.

따라서:

    Edit Mode
        → Current Row 숨김

    View Mode
        → Current Row 표시

---

# 54. Canvas Render State

CanvasRenderer에서 사용하는 상태에도 Mode와 Current Row를 추가하였다.

개념적인 구조:

    export interface CanvasRenderState {
        pattern: PatternData;
        camera: CameraState;
        mode: "edit" | "view";
        currentRow?: number;
        hoverCell?: {
            x: number;
            y: number;
        } | null;
        selection?: Selection | null;
        showGrid?: boolean;
        clipboard?: ClipboardData | null;
        pastePreview?: {
            x: number;
            y: number;
        } | null;
    }

이렇게 하여 CanvasRenderer가 현재 Editor Mode를 알 수 있도록 하였다.

---

# 55. PatternCanvas와 Mode 연결

PatternCanvas에서 Mode와 Current Row를 CanvasRenderer에 전달하도록 변경하였다.

렌더링 Effect의 dependency에도 Mode와 Current Row를 포함하였다.

이를 통해 Edit Mode ↔ View Mode를 전환할 때 Current Row 표시가 즉시 변경되도록 하였다.

---

# 56. View Mode 진입 시 Current Row 초기화

View Mode에 들어갈 때 Current Row를 1로 초기화하도록 Effect를 추가하였다.

    useEffect(() => {
        if (mode === "view") {
            setCurrentRow(1);
        }
    }, [mode]);

따라서 View Mode를 새로 시작하면 항상 Row 1부터 작업을 시작할 수 있다.

---

# 57. Canvas Row 클릭

View Mode에서 원하는 Row를 직접 클릭하면 해당 Row가 Current Row가 된다.

처리 과정:

    Canvas 클릭
        ↓
    Cell 좌표 계산
        ↓
    Canvas Y 좌표 확인
        ↓
    Row 계산
        ↓
    currentRow 변경
        ↓
    Current Row Highlight 변경
        ↓
    Progress 갱신

실제 구현 과정에서 처음에는 Row 변경이 정상적으로 반영되지 않는 문제가 있었으나 Canvas Event와 PatternEditor의 상태 연결을 수정하여 정상적으로 동작하도록 개선하였다.

---

# 58. Row 번호 계산

Canvas 좌표는 위에서부터 증가하지만 실제 작업 Row는 아래에서부터 1로 시작하도록 설계하였다.

따라서 다음과 같은 계산을 사용한다.

    currentRow = patternHeight - y

예:

    patternHeight = 50

    y = 49
    → Row 1

    y = 48
    → Row 2

    y = 0
    → Row 50

이를 통해 오른쪽 아래를 작업 시작점으로 사용하는 방식에 맞출 수 있도록 하였다.

---

# 59. Current Row Progress

현재 작업 중인 Row를 기준으로 전체 Pattern에서 어느 정도 진행했는지를 계산한다.

계산 방식:

    progress =
        Math.round(
            (currentRow / patternHeight) * 100
        );

예:

    Current Row = 25
    Pattern Height = 50

    Progress = 50%

StatusBar에서 다음과 같이 표시할 수 있다.

    Row
    25 / 50

    Progress
    50%

---

# 60. NaN Progress 문제 해결

개발 과정에서 Progress가 `NaN%`로 표시되는 문제가 발생하였다.

원인은 Progress 계산 과정에서 `patternHeight` 값이 올바르게 전달되지 않거나 잘못된 변수를 참조한 것이었다.

이를 Pattern의 실제 Height를 기준으로 계산하도록 수정하였다.

현재는 정상적으로 Progress가 계산된다.

---

# 61. Row Navigation

Current Row를 직접 클릭하는 방법 외에도 이전 / 다음 버튼을 추가하였다.

구조:

    ◀ 이전       다음 ▶

이전:

    currentRow - 1

다음:

    currentRow + 1

단, 범위를 벗어나지 않도록 제한한다.

    최소 = 1
    최대 = pattern.height

---

# 62. Row Navigation 버튼 비활성화

첫 번째 Row에서는 이전 버튼을 비활성화한다.

마지막 Row에서는 다음 버튼을 비활성화한다.

예:

    currentRow <= 1
        → 이전 비활성화

    currentRow >= pattern.height
        → 다음 비활성화

버튼 스타일도 기존 Toolbar / Panel UI와 일관되도록 구성하였다.

# 66. PNG Export 기존 문제

기존 PNG Export에서는 Pixel을 그리는 반복문 내부에서 Grid까지 반복적으로 그리는 구조였다.

개념적으로:

    for each pixel:
        draw pixel

        for each vertical grid:
            draw grid

        for each horizontal grid:
            draw grid

이 구조는 Pixel마다 Grid를 다시 그리는 문제가 있었다.

Pattern 크기가 커질수록 불필요한 반복 작업이 증가할 수 있었다.

---

# 67. PNG Export 개선

PNG Export를 다음 순서로 분리하였다.

    1. Canvas 생성
    2. 모든 Pixel 렌더링
    3. 모든 세로 Grid 렌더링
    4. 모든 가로 Grid 렌더링
    5. PNG 변환
    6. 다운로드

즉 Pixel 렌더링과 Grid 렌더링을 분리하였다.

이로 인해 불필요한 Grid 반복 렌더링을 제거하였다.

# 76. Stitch 기능 보류

Stitch Symbol 기능은 현재 보류하였다.

가장 큰 이유는 원본 PatternData를 유지해야 하기 때문이다.

예를 들어 두 개의 Cell을 하나의 Stitch처럼 보이게 하기 위해 실제 Pixel 데이터를 합쳐버리면 원본 PatternData가 손상될 수 있다.

따라서 다음 구조를 유지하는 방향으로 결정하였다.

    원본 PatternData
          ↓
      그대로 유지
          ↓
    Stitch Rendering
          ↓
    두 Cell을 하나의 Stitch처럼 시각적으로 표시

---

# 77. Stitch 색상 문제

두 개의 Cell을 하나의 Stitch로 표시할 경우 두 Cell의 색상이 서로 다를 수 있다.

예:

    Cell A = Red
    Cell B = Blue

이를 하나의 Stitch로 합치면 어떤 색상을 사용할지 결정해야 한다.

가능한 문제:

- 한 색상만 표시
- 두 색상 표현이 어려움
- 원본 데이터와 화면 표시가 달라짐

따라서 이 문제를 명확하게 해결하기 전까지 Stitch 기능은 보류한다.

# 78. Stitch 기능의 향후 방향

향후에는 PatternData를 변경하지 않고 Render 단계에서 Stitch Symbol을 표현하는 방식을 우선 검토한다.

    PatternData
          ↓
    StitchConverter
          ↓
    Render Model
          ↓
    StitchLayer
          ↓
    Canvas

# 79. Edit Mode / View Mode와 Stitch의 관계

현재는 Stitch 기능을 View Mode에 바로 통합하지 않는다.

우선:

    Edit Mode
    → Pattern 편집

    View Mode
    → Pattern 작업 위치 확인

을 안정적으로 완성한다.

이후 Stitch Symbol 표시 기능을 View Mode와 결합하는 방향으로 확장한다.

# 108. 개발하면서 해결한 주요 문제

## Toolbar Type 문제

`RenderMode`가 실제 타입 파일에서 Export되지 않아 발생한 TypeScript 오류를 해결하였다.

중복 선언된 `renderMode`를 제거하고 실제 필요한 Mode 구조를 정리하였다.

---

# 109. 중복 State 문제

PatternEditor에서 `renderMode`와 관련된 중복 선언이 발생하였다.

중복 State를 제거하고 하나의 Mode 상태를 사용하도록 정리하였다.

---

# 110. Current Row 전달 문제

Current Row를 Canvas Event와 Renderer에 전달하는 과정에서 Props가 복잡해졌다.

특히 `currentRow`가 CanvasEvents에서 직접 필요하지 않은 경우에도 Props로 전달되어 TypeScript 오류가 발생하였다.

이를 확인하여 CanvasEvents에서는:

    patternHeight
    onCurrentRowChange

만 사용하고, 실제 `currentRow` 값은 PatternCanvas와 CanvasRenderer에서 관리하도록 역할을 구분하였다.

---

# 111. Pattern Height 참조 문제

Progress 계산 과정에서 잘못된 `patternHeight` 참조로 `NaN%`가 표시되는 문제가 있었다.

Pattern의 실제 Height를 기준으로 계산하도록 수정하여 정상적인 Progress 표시를 구현하였다.

---

# 112. View Mode Row 변경 문제

처음에는 View Mode에서 Canvas를 클릭해도 Current Row가 제대로 변경되지 않는 문제가 있었다.

CanvasEvents의 MouseDown 처리에서 Mode를 먼저 확인하고:

    View Mode
        ↓
    Row 계산
        ↓
    onCurrentRowChange()

가 실행되도록 수정하였다.

현재는 Canvas의 원하는 Row를 클릭하여 Current Row를 변경할 수 있다.

---

# 113. View Mode Highlight 문제

Edit Mode에서도 Current Row Highlight가 표시되는 문제가 있었다.

CanvasRenderState에 Mode를 추가하고 CanvasRenderer에서:

    state.mode === "view"

인 경우에만 CurrentRowLayer를 렌더링하도록 변경하였다.

또한 PatternCanvas의 Effect dependency에 `mode`를 추가하여 Mode 전환 즉시 화면이 갱신되도록 하였다.

---

# 114. Current Row Highlight 방식 변경

초기에는 Current Row 전체를 반투명한 색상으로 채웠다.

문제:

- Pattern의 실제 색상이 가려짐
- 작은 색상 차이를 보기 어려움

따라서 최종적으로:

    Fill Highlight
        ↓
    Border Highlight

로 변경하였다.

현재는 빨간색 Border로 작업 행을 표시한다.

# 115. PNG Export 성능 문제

PNG Export에서 Pixel 반복문 내부에서 Grid를 반복적으로 그리는 문제가 있었다.

이를:

    Pixel 전체 렌더링
        ↓
    Grid 전체 렌더링

구조로 변경하였다.

이렇게 하여 Grid가 Pixel 수만큼 반복해서 그려지는 문제를 제거하였다.

# 134. 개발 시 유지할 핵심 원칙

앞으로 기능을 추가할 때 다음 원칙을 유지한다.

## 데이터와 화면 분리

    PatternData
        ≠
    Canvas Rendering

PatternData는 원본 데이터를 유지하고 Canvas는 이를 표시하는 역할을 담당한다.

## Engine과 UI 분리

Pattern 수정 로직은 Engine에서 처리하고 Component는 UI와 사용자 입력을 담당한다.

## View Mode는 읽기 전용

View Mode에서는 UI뿐 아니라 Event와 Logic에서도 Pattern 변경을 차단한다.

## 원본 데이터 보존

특히 Stitch 기능처럼 화면 표현을 위해 PatternData를 직접 변경하지 않는다.

## 기능별 책임 분리

Canvas, Palette, Toolbar, Status, Pattern 등의 기능은 가능한 한 독립적으로 관리한다.
