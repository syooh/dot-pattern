# 1. 프로젝트 개요

## 프로젝트명

Dot Pattern Editor

## 프로젝트 목적

이미지를 기반으로 도트 패턴을 생성하고, 생성된 패턴을 웹에서 직접 편집할 수 있는 Editor를 개발한다.

주요 목적은 다음과 같다.

- 이미지를 도트 패턴으로 변환
- 패턴 크기 및 색상 수 지정
- 생성된 패턴 편집
- 색상 Palette 관리
- 패턴 JSON 저장 / 불러오기
- 패턴 PNG 저장
- 뜨개질 작업을 위한 View Mode 제공
- 현재 작업 중인 행 및 진행률 확인
- 향후 사용자별 패턴 저장 및 관리
- 향후 Django + MySQL + JWT 기반 서비스로 확장

5. PatternData 설계

패턴을 관리하기 위한 기본 데이터 구조를 PatternData로 정의하였다.

export interface PaletteColor {
    id: number;
    hex: string;
    name: string;
    code?: string;
    brand?: string;
    symbol?: string;
    count?: number;
}

export interface PatternData {
    width: number;
    height: number;
    palette: PaletteColor[];
    pixels: number[][];
}

export type ToolType =
    | "brush"
    | "eraser"
    | "fill"
    | "select"
    | "move";

PatternData는 다음과 같은 구조를 가진다.

PatternData
├── width
├── height
├── palette
└── pixels

각 Pixel은 Palette의 Color ID를 참조한다.

이를 통해 실제 색상 정보와 Pixel 데이터를 분리하여 관리하였다.

15. PNG Export 개선

PNG Export 기능을 개선하였다.

기존에는 Pixel을 그리는 반복문 내부에서 Grid까지 반복적으로 그리는 구조였다.

이 구조는 Pixel 개수만큼 Grid 렌더링이 반복될 수 있기 때문에 불필요한 작업이 발생하였다.

이를 다음과 같이 변경하였다.

Canvas 생성
    ↓
모든 Pixel 렌더링
    ↓
세로 Grid 전체 렌더링
    ↓
가로 Grid 전체 렌더링
    ↓
PNG 변환
    ↓
다운로드

Pixel 렌더링과 Grid 렌더링을 분리하여 불필요한 반복 작업을 제거하였다.

PNG Export에도 Canvas와 동일하게 10칸 단위 Bold Grid를 적용하였다.

33. Row Navigation

View Mode에서 작업 행을 쉽게 이동할 수 있도록 이전 / 다음 버튼을 추가하였다.

◀ 이전        다음 ▶
이전

현재 행에서 1 감소한다.

최소값은 1이다.

다음

현재 행에서 1 증가한다.

최대값은 Pattern의 전체 높이이다.

첫 번째 행에서는 이전 버튼을 비활성화하고, 마지막 행에서는 다음 버튼을 비활성화하도록 구성하였다.

37. Stitch 기능 보류

Stitch Symbol 기능은 현재 보류하였다.

가장 큰 이유는 원본 PatternData를 유지하면서 Stitch를 표현해야 하기 때문이다.

두 개의 Cell을 하나의 Stitch처럼 표현하기 위해 실제 데이터를 합치면 원본 데이터가 손상될 가능성이 있다.

따라서 다음 방향을 고려하였다.

원본 PatternData
      ↓
그대로 유지
      ↓
View / Stitch Rendering
      ↓
두 Cell을 하나의 Stitch처럼 시각적으로 표시

특히 서로 다른 색상의 두 Cell을 하나의 Stitch로 표현할 경우 어느 색상을 사용할 것인지에 대한 문제가 발생한다.

따라서 현재는 Stitch 기능을 보류하고 Editor와 View Mode를 우선 완성하였다.
